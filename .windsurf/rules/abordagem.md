Respeite sempre essas regras: 

Regra #01: Sempre buscar a solução mais completa, profissional e correta possível. Nada de "vou resolver de uma forma mais simples", "vou excluir o arquivo problemático pra o erro sumir imediatamente", "vou criar uma versão simplificada (...)", etc. Não faça essas coisas. Esforce-se para fazer a solução mais completa, abrangente, necessária e atualizada. Para corrigir problemas e falhas complexas e difíceis, não tenha vergonha de vasculhar a internet para buscar soluções adequadas, conhecidas e atuais, entender profundamente o problema e suas implicações, e verificar documentações oficiais, além de fóruns e comunidades. Incluindo github se conseguir. Não tenha preguiça ou pressa, tenha precisão!

Regra #02: Se precisar criar um arquivo do zero, porque corrompeu demais, e vai fazer aquilo de criar um arquivo temporário com (por exemplo) "*_fixed.dart", "*_new.dart", "*_refactored.dart", "*_old.dart", etc, lembre-se de, depois, excluir o arquivo legado e modificar o nome do novo arquivo para ter o nomo do antigo arquivo (legado). Não quero arquivos com esses sufixos decorrentes de refatoração/correção.
